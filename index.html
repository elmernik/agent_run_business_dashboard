Decisions and why

A test-mode payment link may not go on a public page without an explicit flag
A page carrying a test link claims a payment it cannot accept. The mode is readable off the key, so the check is free and the failure it prevents is a customer trying to pay and silently failing.
2026-08-03 13:33:46
Read the built archive before shipping it, not the exclusion list
Blender builds from the source directory into a subdirectory of it, so anything paths_exclude_pattern misses ships to customers. An exclusion list decays silently as files are added; inspecting the finished zip does not. The first build after dist/ existed packaged a 979KB copy of itself.
2026-08-03 13:33:46
Publish Blender extension versions from ops/blenderext.py; first submission stays Elmer's
The upload API only adds versions to a listing that already exists, and creating a listing is a web-UI action bound to a Blender ID. Verified against the live API: the endpoint is reachable from this container, the multipart body is accepted, and a bad credential returns 401 'Invalid token'. Everything but the token is tested.
2026-08-03 13:33:46
Agent may publish extension versions to extensions.blender.org without approval
Elmer, 2026-08-03. Uploading a new version of an already-listed extension is deployment, not posting: it ships our own code to a listing we hold, broadcasts into no community, and carries no domain-ban risk, so the Reddit reasoning does not transfer. Bounded by the API itself — POST /api/v1/extensions/<id>/versions/upload/ only adds versions to an existing listing. Account creation, token generation and the first submission stay with Elmer permanently; those are identity acts and no interface makes them ours, a browser included. Token goes in .env as BLENDER_EXTENSIONS_TOKEN.
2026-08-03 07:05:07
Report visits, not pageviews, as the traffic number
Cloudflare's rumPageloadEventsAdaptiveGroups exposes both: count is every beacon fire including our own clicking between pages, sum.visits counts only pageloads whose referrer is not this host. On 2026-08-03 the site read 30 pageviews but 20 visits, and /hair-cards/ read 10 pageviews and 0 visits — every view of the priced page was internal navigation. Leading with pageviews would have reported a priced page getting traffic when nobody outside had reached it.
2026-08-03 06:52:30
Free Blender add-on 'Card Normals' as the distribution wedge, published to extensions.blender.org
SEO on a two-page site with no domain authority cannot move for months, and the site has zero external visitors (measured: 20 visits/30d, all from one country with no referrer, i.e. our own verification). extensions.blender.org is the only in-app channel reaching Blender's paying artists: 1,077 free add-ons, one click from inside the app. Chose card normal transfer because (a) extcheck found nothing on the platform naming it — the five 'custom normals' hits all clear or hand-edit normals, none transfers from a proxy; (b) its audience is exactly hair-cards' audience, anyone making hair/foliage/grass cards; (c) it does not cannibalise the $29 product, which makes the cards rather than shading them. Blender's native Data Transfer modifier is the honest incumbent and the page says so.
